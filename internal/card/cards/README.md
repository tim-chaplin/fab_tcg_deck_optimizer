# internal/card/cards

Every implemented Flesh and Blood card lives here, one card per three-file group. This package
holds the concrete types that satisfy `card.Card`, the YAML data they are generated from, and
the hand-written `Play` hooks and riders. Pool-excluded cards sit in the `notimplemented/` and
`unplayable/` subpackages.

## Card file layout

Each card is three files sharing a basename (e.g. `aether_slash`):

1. `<card>.yaml` — name, cost, types, go-again, markers, printed text, and the per-variant
   ID / pitch / attack / defense table. Source of truth for every static field on the
   `card.Card` interface.
2. `<card>_gen.go` — auto-generated by `cmd/cardgen` from the YAML. Owns the variant structs
   and every static method (`ID`, `Name`, `DisplayName`, `Cost` when constant, `Pitch`,
   `Attack`, `Defense`, `Types`, `GoAgain`) plus optional marker methods (`NotImplemented`,
   `Unplayable`, `Dominator`, `NotSilverAgeLegal`, `Universal`). Carries a
   `// Code generated by cardgen. DO NOT EDIT.` header.
3. `<card>.go` — hand-written companion. Owns `Play`, riders, modal predicates, attack-reaction
   targeting, plain-block hooks, on-hit handlers, variable `Cost` / `MinCost` / `MaxCost`, and
   dynamic `GoAgain` (when the body reads runtime state). The generator never touches this file.

The YAML's basename drives the gen file name; the package name comes from the first `.go` file
already in the directory. Card data (name, cost, pitch, attack, defense, type line, printed
text) is transcribed from `github.com/the-fab-cube/flesh-and-blood-cards`.

### Editing a card

Change the YAML, then run `go generate ./internal/card/cards/...`. The `//go:generate`
directive in `generate.go` regenerates every `<card>_gen.go` and rewrites the registry's
`cardsByID` map.

### Adding a new card

1. Drop a `<card>.yaml` with the card's static data and variant table.
2. Run `go generate ./internal/card/cards/...` to emit `<card>_gen.go` and register the card.
3. Add the hand-written `<card>.go` with a `Play` method on each variant struct (vanilla
   cards keep an empty `Play` body) plus any markers / riders. Add a top docstring including
   the printed `Text: "..."` block.

The card's `ID` must exist in `internal/ids/card_ids.go` — add the variant IDs there first,
ordered alphabetically by card name, Red then Yellow then Blue within a family.

## NotImplemented vs Unplayable markers

Both markers exclude a card from the random / mutation deck-construction pools (pre-built
hands still play the card using its static stats):

- `NotImplemented` — placeholder; the card *would* be worth modelling but its printed effect
  isn't simulated yet. Pair it with a `// not implemented: <one-line description>` comment
  above the `NotImplemented()` method. The file lives in `notimplemented/`.
- `Unplayable` — verdict; the card is too weak to want even if fully modelled. No per-card
  rationale in the docstring. The file lives in `unplayable/`.

`ls internal/card/cards/notimplemented/` is the live todo list of cards still to model.
`TestLayout_MarkersStayInSubpackages` enforces that marked cards stay in their subpackage.

## Card docstring rules

The top-of-file docstring covers card-SPECIFIC quirks only: the printed rules text (always
include the `Text: "..."` block), any modelling fudge, and anything surprising about how the
card interacts with the solver. Generic framework plumbing belongs in framework docs, not
repeated per card. Don't restate behaviour already documented by a marker the card carries —
a `Dominator` card doesn't re-explain Dominate.

## Standard rider wiring

The plumbing below is uniform across cards. A card docstring calls out the printed rider and
any modelling fudge, never the wiring itself.

- **Played-from-arsenal go-again** (Fervent Forerunner, Frontline Scout, Performance Bonus, …):
  call `self.GrantGoAgainIfFromArsenal()` at the top of `Play`. It flips `GrantedGoAgain` only
  when this copy came from the arsenal slot.
- **`+N{d}` on arsenal-played defense reactions** (Springboard Somersault, Unmovable, …):
  implement `card.ArsenalDefenseBonus` returning `N`. `CardState.EffectiveDefense` folds it in
  for the arsenal-in copy; `Defense()` itself stays the printed value.
- **Plain-block bonuses** (Battlefront Bastion, Right Behind You, …): implement
  `card.Blocker.Block(g, l, self)`. The attack-turn runner calls `Block` on every plain blocker that
  opts in, with `g.Defenders()` set to the partition's full defender slice (DRs and plain
  blocks). Implementations scan `Defenders()` and flip `self.BonusDefense` for conditional
  buffs ("+1{d} when defending alone", "+1{d} together with another card"); the sim folds
  printed `Defense` + `BonusDefense`, capped by remaining incoming damage.
- **Conditional go-again / dominate grants**: flip `self.GrantedGoAgain` / `self.GrantedDominate`
  inside `Play`; `EffectiveGoAgain` / `EffectiveDominate` honour them. The docstring calls out
  the *condition*, not the flag.
- **`card.VariableCost`** (Amplify the Arknight, Rune Flash, …): the hand-written `Cost(g)`
  reads engine state; the marker exposes static `MinCost` / `MaxCost` for the solver
  pre-screen. Note the printed cost formula in the docstring. Leave `cost:` unset (or set to
  `"variable"`) in the YAML so the generator skips emitting a constant `Cost`.
- **Attack Reactions**: implement `card.AttackReaction.ARTargetAllowed(g, c, mode) bool`
  matching the printed target wording. Most ARs read only the printed type-line (`c.Types(nil)`)
  and ignore `g`; thread `g` through when the predicate reads `c.Cost(g)` or class-aware types.
  The attack-turn runner validates the chosen `Mode` and aborts the permutation on failure. The AR's
  `Play` reads `g.AttackReactionTarget()` (set by the runner before `Play`) and applies the
  buff — `self.GrantAttackReactionBuff(g, l, n)` for `+N{p}` buffs, or a direct verb such as
  `g.AddActionPoints(1)` for a granted action point. ARs cost 0 AP. Modal ARs combine with
  `card.Modal.Modes()` — the predicate dispatches per mode, and `Play` applies the effect
  unconditionally because the runner already validated. Non-modal ARs ignore `mode` (always 0).
- **`OnHit` registrations**: attack cards with "if this hits, do X" append a handler to
  `self.OnHit` inside `Play` via `self.RegisterOnHit(fn)` (or an `OnHitHandler` literal when a
  `Source` / `N` / `LogText` payload is needed). The attack-turn runner finalizes each attack
  post-AR-buff: when `LikelyToHit(self)` is true on the post-buff `EffectiveAttack`, every
  handler in `self.OnHit` fires. Cards adding an on-hit rider to a *different* card (Mauvrion
  Skies, Runic Reaping) append to the target's `OnHit`. Do NOT call `LikelyToHit` directly
  from `Play` — the attack-turn runner owns the gate so AR buffs propagate. Use a top-level handler,
  not an inline closure, so registration stays allocation-free.
- **`NextHit` triggers** (Plunder Run, High Striker, …): cards reading "the next time an X you
  control hits this turn, do Y" register via
  `g.CreateTrigger(self.Card, triggertype.Hit, handler, filter)`. The
  `filter func(card.TypeSet) bool` narrows qualifying hits — `card.TypeSet.IsAttackAction` for
  "attack action card" wording, `card.TypeSet.IsAttack` for the broader "attack" wording that
  includes weapon swings. The attack-turn runner drains matching triggers on each `LikelyToHit`
  attack; non-matching triggers stay queued. Use this — not `OnHit` on a specific `CardState`
  — when the rider must wait across misses for the first qualifying hit.
- **Self-granting on-hit go-again** (Overload, Razor Reflex mode 1): "if this hits, it gains
  go again" flips `self.GrantedGoAgain = true` inside `Play` when `g.LikelyToHit(self)` is true.
- **Modal "Choose 1" cards** (Captain's Call, …): implement `card.Modal.Modes() int` and
  dispatch on `self.Mode` inside `Play`. The attack-turn runner enumerates the cartesian product of
  modes across modal cards and picks the highest-value tuple. No-op modes resolve as
  zero-value no-ops. The docstring calls out each mode's effect.
- **Modal cost** (Bluster Buff / Chest Puff / Look Tuff cycle): modal cards whose resource
  cost varies by mode implement `card.ModalCost.ModalCost(mode int8) int`. The attacker meta
  cache folds per-mode min/max into the partition pre-screen. The docstring calls out each
  (cost, effect) pair. Mode 0 is conventionally the printed default.
- **Modal blockers** (Brothers in Arms, …): plain blockers with mode-dependent block-time cost
  implement `card.Modal.Modes()` + `card.Blocker.Block` + `card.BlockCost(mode int8) int`. The
  sim enumerates modes within the spare defense budget and picks the highest-`BonusDefense`
  mode that fits. Mode 0 is the printed default (cost 0, no extra effect).
- **`card.DefensiveInstant`** (Brush Off, Calming Breeze, Oasis Respite, Peace of Mind, …):
  `TypeInstant` cards whose printed effect prevents damage opt in via this marker. The
  partition treats them as defenders; `Cost()` is summed against the defense budget; the sim
  caps `EffectiveDefense` at incoming damage. Damage prevention collapses against the single
  incoming-damage bucket: "the next N damage" and "the next K times … prevent 1 each" both
  reduce to `Defense() = N`. Conditional riders that modify the prevented amount bump
  `self.BonusDefense`. The docstring notes the printed prevention amount and any dropped rider.
- **Optional additional costs** (Looking for a Scrap, Nimble Strike, Regurgitating Slog, …):
  "you may pay X" gates where the cost spends state the sim doesn't otherwise value, for a
  strictly-upside buff, are paid unconditionally — the sim doesn't enumerate the skip branch.
  The docstring notes the printed gate; no per-card rationale for "always tries".

## Logging idioms

A card's `Play` body does NOT emit its own attack step — `sim.ResolveAttackStep` runs `Play`,
credits `g.Value`, and appends the canonical `<Card>: <VERB> (+N)` attack-step entry. `Play`
emits rider sub-lines only, via `l.AppendPostTrigger*` (self-riders) or `l.AppendPreTrigger*`
(hero / aura triggers).

A line starting with `l.AppendXxx(...)` must have no side effects — put the value change on
its own preceding line so a reader scanning for "what does this card do" can skip every
`l.Append` line. Conditional self-buffs (`self.BonusAttack += 2`) go in the `Play` body before
the attack step is logged; `ResolveAttackStep` reads the buffed `EffectiveAttack` after `Play`
returns.

## Important files

- `<card>.yaml` / `<card>_gen.go` / `<card>.go` — the three-file groups.
- `generate.go` — holds the `//go:generate` directive for the package.
- `notimplemented/` — cards carrying the `NotImplemented` marker.
- `unplayable/` — cards carrying the `Unplayable` marker.

## Gotchas and invariants

- Never edit `<card>_gen.go` by hand — regenerate from the YAML.
- Aura / item / on-hit / trigger handlers must be top-level functions, not inline closures —
  closures assigned to a handler field escape to the heap and allocate per `Play`.
- Marked cards must live in `notimplemented/` or `unplayable/` (lint-enforced); plain cards
  must not.
- The card file must not call `g.AddResourcePoints` without also implementing
  `card.ResourceSource` (lint-enforced).
- Vanilla attack / DR / non-attack cards keep an empty `Play` body.
