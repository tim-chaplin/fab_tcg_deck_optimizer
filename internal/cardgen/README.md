# internal/cardgen

The code generator that turns `<card>.yaml` data files into Go source. It emits a sibling
`<card>_gen.go` of static struct and method declarations for each card, plus the registry's
`cardsByID` map. `cmd/cardgen` is the thin CLI wrapper that writes the output to disk;
`internal/lint`'s staleness test calls `Generate` and diffs the result against the committed
files.

## Key types

- `CardGroup` — one card with its pitch variants. Group-level fields (`Name`, `Types`,
  `Universal`, `Cost`, `GoAgain`, `DynamicGoAgain`, `Markers`, `Text`) hold uniform across
  every printing of a card.
- `Variant` — one pitch printing: `ID`, `Pitch`, `Attack`, `Defense`. `Defense` lives here,
  not on the group, because cards print different defense per pitch.
- `Generate(dirs, registryPath)` — the entry point. Returns a `map[outputPath][]byte` of
  gofmt-formatted Go source: one `<card>_gen.go` per YAML in `dirs`, plus the registry file at
  `registryPath` (built from the dir whose package is `cards`) when `registryPath` is non-empty.

## YAML schema

```yaml
name: Aether Slash
types: [Runeblade, Action, Attack]
cost: 1                 # int constant; omit or use "variable" for VariableCost cards
goAgain: false          # default false
dynamicGoAgain: false   # when true, the generator skips GoAgain; the hand file owns it
universal: false        # when true, Types(g) ORs in the active hero's class
markers: [Dominator]    # NotImplemented, Unplayable, Dominator, NotSilverAgeLegal
text: |
  Printed rules text...
variants:
  - id: AetherSlashRed
    pitch: 1
    attack: 4
    defense: 3
```

## What the generator emits

For each variant: a zero-size struct and its static methods (`ID`, `Name`, `DisplayName`,
`Cost` when the cost is constant, `Pitch`, `Attack`, `Defense`, `Types`, `GoAgain` unless
`dynamicGoAgain`), plus one method per entry in `markers`. A package-level types var
(`<cardName>Types`) is shared across the card's variants. The registry file lists every
variant of every group indexed by `ids.CardID`.

The hand-written `<card>.go` companion supplies `Play` and any per-card riders, variable
`Cost` / `MinCost` / `MaxCost`, modal predicates, and attack-reaction targeting. The generator
never touches it.

## Important files

- `cardgen.go` — the whole package: schema structs, `genGroup`, `genRegistry`, `Generate`.

## Gotchas and invariants

- The output package name is read from the first non-test, non-generated `.go` file in each
  directory — a directory with only YAML files cannot be generated into.
- Variable-cost cards must leave `cost:` unset or set it to `"variable"`; the hand file then
  owns `Cost` / `MinCost` / `MaxCost`.
- The generated files carry a `// Code generated by cardgen. DO NOT EDIT.` header — they are
  regenerated, never hand-edited.
- `Generate` only emits the registry file from the directory whose package is `cards`.
